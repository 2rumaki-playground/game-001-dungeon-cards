# カード仕様

## 共通仕様
すべてのカードは以下を持つ：
- 名前
- AP コスト
- 効果
- 使用条件
- レアリティ（UI表示用の希少度分類）
- キーワード（属性タグ）：炎 or 水（詳細は後述）

### 方向パラメータについて
一部のカード（移動カード、攻撃カードなど）は、カード使用時に**方向を選択**する必要がある。
- 方向はカードの固有属性ではなく、**使用時のパラメータ**として扱う
- 同じカード種別（例：移動カード）は1つのカードIDで管理され、デッキ内に複数枚存在する
- 使用時にプレイヤーが上/下/左/右の4方向から選択する
- この設計により、データ管理（カードID、重複カード数、UI表示）がシンプルになる

### キーワード（属性タグ）

すべてのカードは「キーワード（属性タグ）」を**1つ**持つ。キーワードはコンボシステム・条件カード・カード進化の基盤となる。

#### キーワード一覧

| キーワード | ID | 説明 |
|---|---|---|
| 炎 | `flame` | 攻撃的な火の力。炎優勢時にダメージ系の効果補正が増加する |
| 水 | `water` | 流動する水の力。水優勢時に回復・防御系の効果補正が増加する |

#### カード種別とキーワードの関係

すべてのカード種別に対して、炎バリアントと水バリアントが存在する。
具体的なデータモデル拡張方式（Card型へのフィールド追加、CardTypeの分割、マッピング構造など）は実装時に決定する。

| カード種別 | 炎バリアント | 水バリアント |
|---|---|---|
| move | 炎の移動 | 水の移動 |
| attack | 炎の攻撃 | 水の攻撃 |
| strong_attack | 炎の強攻撃 | 水の強攻撃 |
| jump | 炎のジャンプ | 水のジャンプ |
| wait | 炎の待機 | 水の待機 |

※ `heal` / `pierce` カードは v1.2 で追加予定のため、本表には含めていない。実装時にキーワードを割り当てる。

- カードの効果自体はキーワードによって変わらない（炎の攻撃も水の攻撃も基本ダメージは同じ）
- キーワードは属性バランスシステムを通じて効果補正に影響する

#### キーワードの割り当てタイミング

- **初期デッキ**：ラン開始時にカードごとにランダムで炎または水を割り当てる
- **カード報酬**：報酬候補として提示される時点でキーワードが決定されている（例：「炎の攻撃カード」「水の移動カード」として選択肢に出る）

#### 属性バランスシステム

プレイヤーは「炎カウンター」と「水カウンター」を持つ：

- 初期値はともに 0
- 炎属性のカードを使用すると炎カウンター **+1**
- 水属性のカードを使用すると水カウンター **+1**
- カウンターは **1ラン全体**（ニューゲーム〜ゲームオーバーまたはクリア）を通じて累積する
- ニューゲーム時にリセットされる

**バランス値** = 炎カウンター − 水カウンター

#### 属性ボーナス

バランス値に応じて、カード使用時のダメージ・回復量に補正がかかる：

- **バランス値 > 0**（炎優勢）：炎カードの効果に正の補正、水カードの効果に負の補正
- **バランス値 < 0**（水優勢）：水カードの効果に正の補正、炎カードの効果に負の補正
- **バランス値 = 0**：補正なし

具体的な補正値・計算式は [constants.md](./constants.md) を参照。

## 移動カード

### 仕様
- カード種別：移動カード（1種類のカードIDとして扱う）
- **方向パラメータ**：使用時にプレイヤーが方向を選択（上 / 下 / 左 / 右）
- APコスト：[constants.md](./constants.md) を参照
- 効果：選択した方向に1マス移動
- 移動失敗条件（いずれの場合もAPは消費され、カードは使用扱いとなり捨て札へ移動）：
  - 移動先がマップ外（境界を超える場合）
  - 移動先が壁タイル
  - 移動先に敵が存在する場合
- 移動成功時、移動先のタイルに応じた効果が発生する
  - 階段タイルに到達した場合：階層遷移が発生（詳細は [rules.md](./rules.md) の「階層遷移」を参照）

### データ表現
- 実装上、移動カードは単一のカードID（例：`card_move`）を持つ
- デッキ内では同じカードIDが複数枚存在する（枚数は [constants.md](./constants.md) を参照）
- カード使用時、UIで4方向から1つを選択するインターフェースを提供する
- テストでは `{cardId: "card_move", direction: "up"}` のような形式で表現可能

## 攻撃カード

### 仕様
- カード種別：攻撃カード（1種類のカードIDとして扱う）
- **方向パラメータ**：使用時にプレイヤーが方向を選択（上 / 下 / 左 / 右）
- APコスト：[constants.md](./constants.md) を参照
- 効果：選択した方向1マス先の敵にダメージを与える（ダメージ量は [constants.md](./constants.md) 参照）

### 攻撃の成立条件
攻撃が成立するのは以下の条件をすべて満たす場合のみ：
- 指定方向1マス先がマップ内（境界内）である
- 指定方向1マス先が壁タイルではない
- 指定方向1マス先に敵が存在する

### 攻撃の不成立
攻撃が不成立となるケース：
- 指定方向1マス先がマップ外（境界を超える場合）
- 指定方向1マス先が壁タイル
- 指定方向1マス先に敵が存在しない（床、階段、またはプレイヤー自身のみの場合）

**いずれの場合も AP は消費され、カードは使用扱いとなり捨て札へ移動する**

### データ表現
- 実装上、攻撃カードは単一のカードID（例：`card_attack`）を持つ
- デッキ内では同じカードIDが複数枚存在する（枚数は [constants.md](./constants.md) を参照）
- カード使用時、UIで4方向から1つを選択するインターフェースを提供する
- テストでは `{cardId: "card_attack", direction: "down"}` のような形式で表現可能

## ジャンプカード

### 仕様
- カード種別：ジャンプ（CardType: "jump"。同種のカードが複数枚デッキに存在し得る）
- **方向パラメータ**：使用時にプレイヤーが方向を選択（上 / 下 / 左 / 右）
- APコスト：[constants.md](./constants.md) を参照
- 効果：選択した方向の**2マス先**に直接着地する（1マス先を飛び越える）

#### 解決処理
ジャンプカードは以下の順序で処理される：

1. **着地先（2マス先）の判定**
   - 着地先がマップ外の場合：
     - **ジャンプ失敗**：プレイヤーは移動せず、その場に留まる
     - APは消費される
     - 処理終了
   - 着地先が壁タイルの場合：
     - **ジャンプ失敗**：プレイヤーは移動せず、その場に留まる
     - APは消費される
     - 処理終了
   - 着地先に敵が存在する場合：
     - **ジャンプ失敗**：プレイヤーは移動せず、その場に留まる
     - APは消費される
     - 処理終了
   - 着地先が床、階段、または特殊タイルで、敵が存在しない場合：
     - **ジャンプ成功**：2マス先に直接移動
     - 着地先の判定へ進む

2. **着地先の階段判定**
   - 着地先が階段の場合：
     - **階層遷移が発生**（[rules.md](./rules.md) の「階層遷移」を参照）
     - 処理終了
   - 着地先が床または特殊タイルの場合：
     - 特殊タイル効果判定へ進む

3. **着地先の特殊タイル効果**
   - 着地先が特殊タイルの場合：
     - 着地先のタイル効果のみ発動する
   - 着地先が通常床の場合：
     - 処理終了

#### 飛び越えルール
- 1マス先の**敵・壁・階段・特殊タイル**を飛び越えられる
- 飛び越えたマスの効果は**一切発動しない**（罠ダメージなし、宝箱開かない、階段も無視）
- 1マス先が壁でも、2マス先が有効な床タイルであればジャンプ可能

#### 重要な仕様
- **APは常に消費され、カードは使用扱いとなり捨て札へ移動する**（ジャンプが失敗した場合も含む）
- 着地先のみで階段判定・特殊タイル効果判定が行われる
- 他のキャラクター（敵）との衝突では、ジャンプが失敗するのみで、ダメージは発生しない（攻撃カードではないため）
- ※ 移動可否判定の詳細は `rules.md` の「移動可否の判定」を参照（正）

### データ表現
- ジャンプカードのカード種別（CardType）は `"jump"` である
- 各カードインスタンスはユニークなID（例：`card-1`, `card-2`）を持ち、種別（type）で区別される
- デッキ内では同じ種別のカードが複数枚存在する（枚数は [constants.md](./constants.md) を参照）
- カード使用時、UIで4方向から1つを選択するインターフェースを提供する
- テストでは `{cardId: "card-1", direction: "right"}` のような形式で表現可能

## 回復カード（v1.2追加）

### 仕様
- カード種別：回復カード（1種類のカードIDとして扱う）
- 方向パラメータ：なし
- APコスト：[constants.md](./constants.md) を参照
- 効果：プレイヤーのHPを回復する（回復量は [constants.md](./constants.md) 参照）
- HP上限：プレイヤーの初期HP（[constants.md](./constants.md) 参照）を超えない
- 成立条件：**常に成立**（HPが最大でもAP消費してカード使用扱いとなり捨て札へ移動する）

### データ表現
- 実装上、回復カードは単一のカードID（例：`card_heal`）を持つ
- 方向選択は不要（使用時に即座に効果が発動する）
- テストでは `{cardId: "card_heal"}` のような形式で表現可能

## 貫通攻撃カード（v1.2追加）

### 仕様
- カード種別：貫通攻撃カード（1種類のカードIDとして扱う）
- **方向パラメータ**：使用時にプレイヤーが方向を選択（上 / 下 / 左 / 右）
- APコスト：[constants.md](./constants.md) を参照
- 効果：選択した方向に射程（[constants.md](./constants.md) 参照）マスまで貫通し、射程内の**全ての敵**にダメージを与える（ダメージ量は [constants.md](./constants.md) 参照）
- 射程：[constants.md](./constants.md) 参照（壁で遮断される）

### 攻撃の成立条件
攻撃が成立するのは以下の条件をすべて満たす場合のみ：
- 指定方向の射程内（壁で遮断されるまで）に敵が1体以上存在する

### 攻撃の不成立
攻撃が不成立となるケース：
- 射程内（壁で遮断されるまで）に敵が存在しない

**いずれの場合もAPは消費され、カードは使用扱いとなり捨て札へ移動する**

### データ表現
- 実装上、貫通攻撃カードは単一のカードID（例：`card_pierce`）を持つ
- デッキ内では同じカードIDが複数枚存在しうる
- カード使用時、UIで4方向から1つを選択するインターフェースを提供する
- テストでは `{cardId: "card_pierce", direction: "up"}` のような形式で表現可能
