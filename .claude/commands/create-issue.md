# Issue作成

引数 `$ARGUMENTS` にIssueの概要（1行の要約）が渡される。

## 手順

### 1. コンテキスト収集

引数の概要をもとに、関連しそうなコードや仕様を調査する。

- `docs/spec/` 配下の仕様ドキュメントを確認
- `src/` 配下の関連コードを確認
- 既存Issueとの重複チェック: `gh issue list --state open --limit 30 --json number,title`

重複がある場合はユーザーに報告し、続行するか確認する。

### 2. 対話的にIssue内容を決定

AskUserQuestion を使い、以下の項目を順に確認する。
一度の質問で聞く項目は最大4つまで。関連する項目をまとめて聞く。

#### 質問1: 種別とラベル

| ラベル | 用途 |
|--------|------|
| `bug` | バグ修正 |
| `enhancement` | 新機能・機能追加 |
| `documentation` | 仕様・ドキュメント |
| `refactor` | リファクタリング |
| `ui/ux` | UI/UXの改善・演出 |
| `perf` | パフォーマンス改善 |
| `test` | テストの改善 |

ユーザーに種別を選んでもらう（複数選択可）。
調査結果から適切な種別を推薦し、最初の選択肢に `(Recommended)` をつける。

#### 質問2: 詳細の確認

調査結果をもとに以下の草案を提示し、ユーザーに確認・修正してもらう：

- **タイトル**: 何をするかを1行で（日本語、50文字以内）
- **背景/問題**: なぜこのIssueが必要か
- **該当箇所**（仕様の曖昧さに関するIssueの場合は **参照**）: 関連ファイル・仕様の参照（調査で見つかったもの）
- **受け入れ条件**: 何が達成されれば完了か（チェックリスト形式）

草案を提示したうえで「この内容で作成しますか？修正があれば教えてください」と確認する。

### 3. Issue作成

確定した内容で Issue を作成する。

```bash
gh issue create \
  --title "<タイトル>" \
  --label "<label1>,<label2>" \
  --body "$(cat <<'EOF'
## 背景

<背景/問題の説明>

## 該当箇所

<関連ファイルパス・仕様参照>

## 受け入れ条件

- [ ] <条件1>
- [ ] <条件2>
- [ ] 既存テストが全て通る
EOF
)"
```

仕様の曖昧さに関するIssueの場合、CLAUDE.md のガイドラインに従い「該当箇所」を「参照」に置き換える:

```bash
gh issue create \
  --title "Issue: <何が未定義/曖昧かを1行で>" \
  --label "<label1>,<label2>" \
  --body "$(cat <<'EOF'
## 参照

<該当ファイルと行または見出し>

## 背景 / 問題

<実装・テスト・UXで何が困るか>

## 受け入れ条件（DoD）

- [ ] <何が決まれば完了か>
- [ ] 既存テストが全て通る
EOF
)"
```

### 4. 結果報告

作成されたIssueのURLを表示する。

## ルール

- すべての出力は日本語
- タイトルは日本語、50文字以内
- 受け入れ条件には必ず「既存テストが全て通る」を含める（documentation ラベルのみの場合は除く）
- 仕様の曖昧さに関するIssueの場合、CLAUDE.md のガイドラインに従う:
  - **タイトル**: Issue: 何が未定義/曖昧かを1行で
  - **参照**: 該当ファイルと行または見出し
  - **背景 / 問題**: このままだと実装・テスト・UXで何が困るか
  - **受け入れ条件（DoD）**: 仕様として何が決まれば完了か
- 調査で関連する仕様ドキュメントが見つかった場合、受け入れ条件に仕様の更新も含める
